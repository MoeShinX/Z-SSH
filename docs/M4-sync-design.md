# M4 设计：配置同步与备份

2026-10-15 起草。用户决定：**只做配置同步**（主机、凭据、设置加密后上云），不做服务器数据备份。5 种存储都要。

参考 Netcatty：
- `domain/sync.ts`：同步什么
- `infrastructure/services/EncryptionService.ts`：加密
- `infrastructure/services/adapters/*Adapter.ts`：5 种存储
- `domain/syncGuards.ts`：防止误删
- `domain/convergentSync/`：多设备合并
- `electron/bridges/vaultBackupBridge.cjs`：本地自动备份
- `electron/bridges/{github,google,onedrive}AuthBridge.cjs`：登录
- 界面：`components/cloud-sync/`

## 1. 同步什么

- **同步**：分组、主机、凭据（含密码、私钥、口令）、代理（含密码）、自己的 known_hosts、设置（主题、终端选项、默认代理、默认智能体、SFTP 传输参数等；完整清单见 `crates/zssh-core/src/sync/settings.rs`，有测试守着）
- **不同步**：AI 审计日志、窗口状态、数据目录路径这类本机相关的东西；**AI 执行模式（`ai_exec_mode`）也不同步**（R-6 F06）——它是权限设置，决定 AI 的命令要不要逐条人工批准，不能让另一台电脑通过同步把这台电脑从"手动审批"提升成"自动执行"，所以只在本机改；导入同步包时，不在白名单里的设置键一律忽略；**面板宽度这类布局设置也不同步**（`settings` 表里的 `layout.*` 键，如 `layout.ai_panel_width` / `layout.aside_panel_width`，UI-1 加的）——不同电脑屏幕大小不一样，同步过去只会把对方的面板挤变形

### 1.1 设置的新旧版本兼容（R-7b）

v0.1 是第一个公开版本，不升级的用户会一直留着它的同步行为，而以后每加一个同步设置、每扩一个取值范围，旧版本和新版本的电脑就会一起同步同一份云端包。合并设置时，**按“这个版本认不认识这个键 / 这个值”分三类处理**，规则由 `crates/zssh-core/src/sync/settings.rs` 的 `prepare_for_merge` 实现：

| 类别 | 例子 | 合并 | 上传的包和基线 | 写进本机 |
| --- | --- | --- | --- | --- |
| 1. 本版本标成**只在本机**的键（含同步引擎的内部状态键） | `ai_exec_mode`、智能体路径、`sync_*`、`layout.*` | 三份里都丢掉，记一条日志 | **不进** | 不写 |
| 2. 本版本**根本不认识**的键（不在白名单表里） | 更新版本新加的同步设置 | 原样带过合并，不检查值 | **保留** | **永远不写** |
| 3. 本版本认识的**同步键** | `ui_theme`、`terminal_font_size` 等 | 照常三方合并；对方的值本版本不接受时也留在合并结果里 | 保留（对方的值） | 值通过本版本的取值检查才写；不通过就保留本机原值，记日志 |

要点：

- **第 2 类有大小限制**，免得一个坏包无限撑大同步包：单个值序列化后不超过 4096 字节，不认识的键最多 200 个（按键名排序留前 200 个），超出的丢掉并记日志。不检查它的内容。
- **第 3 类“本机没改过就不能覆盖云端”**。对方的值本版本不接受（比如更新版本的新主题），本机保留的是自己原来的值。如果合并时把本机的旧值当成“本机的修改”，旧版本会把云端的新值改回旧值。所以：
  - 本机用一个**待定记录**记下“这个键因为值不接受没写进本机，当时本机的值是 X”（本机设置 `sync_pending_settings`，只在本机，不同步）。每次同步 / 导入成功之后整体重算：目标里这个键的值本版本不接受、并且本机有值、值和目标不一样，就记下本机的值。
  - 下一次合并时，本机这个键的值**还等于记录里的值**，就说明用户没动过，合并时把本机这一份当成“没有意见”，云端的值保留；用户改成了别的值（不等于记录），按正常的“后改的赢”规则上传。
  - 没有基线（第一次同步）时没法证明本机的值是用户改的：对方的值本版本不接受，同样按“没有意见”处理。
  - 旧版本升级成认识这个值的版本后，本机“没有意见”，云端的值被正常写进本机，记录随之清掉。
- **写库那一层保持原样**：`apply` 只写本版本认为合格的同步键，第 1、2 类和不合格的值一律不写，所以本机永远只有本版本认为合格的值。
- 合并结果里这些本机不会写的键，和本机的差别**不算“要改本机”**（`same_data_for_local`），否则每次同步都会白白备份和写库一次。
- 正式代码只有一套规则（`SettingsPolicy::CURRENT`）。测试里用 `SyncEngine::with_policy` 注入另一套，模拟“更新版本”和“旧版本”的电脑一起同步。
- **加同步设置时的约定**：新键进 `SETTINGS_SYNC_CLASS` 标 `Synced`，同时在 `rule_for` 里写取值规则（有测试守着）。旧版本拿到它会按第 2 类带过，不会丢；扩已有键的取值范围同理，旧版本按第 3 类处理，不会改回去。要**收窄**范围或把同步键改成只在本机，则会让旧版本里仍有的值变成“不接受”，同样安全，但新版本这边要自己决定怎么处理已经上云的旧值。

## 2. 加密（零知识）

- 用户设置一个**主密码**，云端只存密文
- 主密码 → **Argon2id**（参数写进密文头，以后可以升级）→ 256 位密钥 → **XChaCha20-Poly1305** 加密整个同步包。Netcatty 用的是 PBKDF2 + AES-GCM，Argon2id 抗暴力破解更强
- 密文格式带版本号：`{format, version, kdf 参数, salt, nonce, ciphertext}`
- **主密码不落盘**。可以选择"在这台电脑上记住"，用 DPAPI 加密后存在本地
- **DPAPI 密文不能直接同步**，因为它绑定在这台电脑的这个 Windows 用户上。导出时先用 DPAPI 解开，放进同步包，整体用主密码加密；导入时解开同步包，再用本机的 DPAPI 重新加密存入数据库
- 修改主密码：重新加密并上传
- 忘记主密码就无法恢复云端数据。界面上要明确提示

## 3. 记录标识与合并

- 现在数据库用的是自增整数 ID，换一台电脑就对不上。新迁移给 groups、hosts、identities、proxies 加一列全局唯一的 `uid`（UUID），老数据迁移时生成。同步包里的引用关系（比如主机引用了哪个凭据）一律用 `uid`
- **合并**用三方比较：本地当前状态、云端当前状态、**上次同步成功时的状态**（基线，本地保存一份）
  - 只有一边改了 → 用改了的那边
  - 两边都改了同一条记录 → 用修改时间较新的，并记成"冲突"，在界面上列出来，让用户可以改回另一边的版本
  - 删除用"墓碑"记录，保留 90 天，防止删掉的东西被别的设备同步回来
- Netcatty 做的是字段级的合并，更细但复杂得多。我们先做**记录级**，以后有需要再细化

## 4. 防止误删

参考 `syncGuards.ts`：如果这次同步会删掉超过一半的记录，或者删掉的主机超过 10 台，就暂停，让用户选：继续、改用云端版本覆盖本地，或者取消。

## 5. 本地自动备份

- 在数据目录的 `backups/` 下保存加密快照，用 DPAPI 加密
- 以下时机自动备份：每次从云端合并之前、每次恢复之前、应用版本升级后第一次启动时
- 最多保留 20 份，可以设置
- 界面上可以查看备份列表，并恢复到任意一份

## 6. 存储

统一接口：读取对象、写入对象（带版本号，做乐观并发控制）、删除。云端只存一个文件（`zssh-sync.json`）。

| 存储 | 登录方式 | 并发控制 | 说明 |
| --- | --- | --- | --- |
| WebDAV | 地址 + 用户名 + 密码 | ETag + `If-Match` | 自建 Nextcloud、坚果云、Alist 等 |
| S3 兼容 | Endpoint、Region、Bucket、Access Key、Secret | ETag / 版本 | AWS、R2、MinIO、阿里云 OSS。签名用轻量库（比如 `rusty-s3`），不引入完整的 AWS SDK；支持路径风格的地址 |
| GitHub | **个人访问令牌**（经典令牌勾 `gist`，或细粒度令牌的 Gists 读写），存进 **secret Gist**（只放 `zssh-sync.json` 一个文件） | `PATCH` 不支持条件写入：写之前再读、比较 `history` 里最新的 `version`，写完再读一次确认 | 设备码登录要先注册 OAuth 应用，本期不做 |
| OneDrive（S-4） | **浏览器授权登录**：授权码流程 + PKCE（S256），无客户端密钥，回调到本机 `http://localhost:<随机端口>`；权限 `Files.ReadWrite.AppFolder` + `User.Read` + `offline_access`；**只支持个人微软账号**（授权地址用 `consumers`） | `eTag`：写入走 `createUploadSession`，更新带 `If-Match`，首次上传用 `conflictBehavior=fail`；412 / 409 都按“云端被别人改了”重读合并 | 同步包放在应用专用文件夹 `Apps/<应用名>`（`/me/drive/special/approot`），看不到用户的其他文件；**client ID 由发布者在 Azure 注册后编进程序**，自己编译的版本可以在“高级”里填自己的 |
| Google Drive | **不做**（2026-10-21 用户决定） | - | - |

- **GitHub 的 Gist 没有真正“私有”的**：secret Gist 不会出现在公开列表和搜索里，但**任何拿到链接的人都能读**。同步包是用主密码整体加密的，所以内容安全；界面和文档里一律写“secret Gist”，不写“私有 Gist”。Gist 链接不要发给别人
- GitHub 的特殊情况：接口返回的文件内容过大会被截断（`truncated: true`），这时改读 `raw_url` 并核对长度；限流（403 / 429 加 `Retry-After` 或剩余次数为 0）按响应头里的时间等待，等待期内不再发请求，也不自动同步；接口地址可配置（默认 `https://api.github.com`，GitHub Enterprise 填 `https://域名/api/v3`）
- **所有网络请求走 Z-SSH 的默认代理设置**。在国内访问 Google、GitHub 通常需要代理
- 令牌和密码都用 DPAPI 加密后存在本地
- **OneDrive 的登录与令牌（S-4，2026-10-21 用户决定只做 OneDrive，GitHub 维持个人访问令牌，Google Drive 不做）**：
  - 登录：点“用微软账号登录”→ Z-SSH 校验网址（必须是 `https://login.microsoftonline.com/` 开头）后用系统默认浏览器打开微软登录页 → 用户授权 → 浏览器跳回本机回环地址（同时监听 `127.0.0.1` 和 `[::1]` 的同一个随机端口；只接受一次回调、校验 `state`、别的路径一律 404、5 分钟没完成就关闭监听）→ Z-SSH 用授权码 + PKCE verifier 换令牌。换令牌和调用接口走“软件网络代理”；浏览器那一步用系统浏览器自己的网络设置
  - 令牌：访问令牌 + 刷新令牌用 DPAPI 加密存在本机的 `sync_onedrive_tokens`（只在本机，不进同步包、不进离线备份、不进日志）；访问令牌快过期时用刷新令牌换新，微软会轮换刷新令牌，拿到新的就替换保存；刷新令牌失效（被撤销 / 太久没用）按“凭据被拒”处理：暂停自动同步，提示“OneDrive 登录已失效，请重新登录”。断开连接只删本机的令牌和连接设置；个人账号没有简单的撤销接口，界面上给出微软账户“应用和服务”页面的链接让用户自己撤销
  - client ID：公共客户端的 client ID 不是秘密，但不写进代码——构建时从环境变量 `ZSSH_ONEDRIVE_CLIENT_ID` 读取编进程序，发布工作流从仓库 Variables 取；没编进去的版本，“登录”按钮不可用并说明原因，“高级”里可以填自己的 client ID（只存本机，不同步）。注册步骤见 `docs/release.md`
  - 账号类型：官方文档里 `Files.ReadWrite.AppFolder` 的委托权限只对个人账号有效（OneDrive 权限参考页明确写了 “only valid for personal accounts”），应用专用文件夹对工作 / 学校账号的支持说法互相矛盾，所以**只做个人账号**
  - 写入：不用简单上传（`PUT .../content`）——官方文档没有说明它支持 `If-Match`；`createUploadSession` 明确支持 `If-Match`。所以所有写入都先建上传会话，再把同步包 `PUT` 到会话地址（同步包最大 64 MiB，分片按 5 MiB 切，是 320 KiB 的整数倍）。`If-None-Match: *` 在官方文档里没有出处，首次上传改用 `@microsoft.graph.conflictBehavior=fail`（已存在返回 409）。残余风险：会话创建和最后一片提交之间的几百毫秒里别人改了文件，仍可能覆盖；“测试连接”会真实验证 `If-Match` 是否被执行，不支持就退回“写前再读”

## 7. 同步时机

- 手动："立即同步"按钮
- 自动：配置变化后 30 秒（防抖）、应用启动时、每 15 分钟一次（可以设置或关闭）
- 失败时在状态栏和同步页显示原因，不弹窗打扰

## 8. 界面

参照 Netcatty 的 `components/cloud-sync/`，在设置页加"同步"分组：

- 选择存储并连接，显示连接状态
- 设置或修改主密码
- 上次同步的时间和结果，冲突列表
- 本地备份列表，可以恢复
- "在这台电脑上记住主密码"开关
