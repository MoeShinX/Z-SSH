# M3 设计：SFTP 文件管理（对标 Xftp）

2026-10-15 起草。界面参考 Netcatty 的 `components/sftp/`、`SftpView.tsx`、`SftpSidePanel.tsx`；传输逻辑参考 `electron/bridges/sftpBridge.cjs` 和 `transferBridge.cjs`（7600 行，里面有大量边界情况的处理）。

## 1. 目标

- **双栏文件管理**：左边本地、右边远端，像 Xftp 一样拖来拖去
- **终端旁的 SFTP 面板**：见第 3.2 节（2026-10-17 用户决定）
- **可靠的传输**：队列、进度、速度、暂停、续传、失败重试、冲突处理

## 2. 后端

### 2.1 SFTP 会话

- 用 `russh-sftp`（3.x）在**连接池里已有的连接**上开 `sftp` 子系统通道，不需要重新认证
- 同一条连接上的 SFTP 通道复用：浏览目录、读属性、小文件操作共用一个；传输任务按需另开通道，以便并发
- 传输期间如果发现被同一连接上的终端刷屏拖慢（设计文档 M1 第 4.1 节），再改成传输专用一条连接。先实测再决定

### 2.2 文件操作

列目录（含符号链接解析）、读属性、新建文件夹、重命名、删除（递归删除时显示进度、可以取消）、修改权限、新建空文件、读写小文本文件（给 AI 和"快速编辑"用）。

### 2.3 传输引擎

- **任务队列**：上传、下载，单个文件或文件夹（递归展开成文件列表）
- **并发**：同时进行的文件数可以设置（默认 3）；单个大文件用多个请求流水线读写，以提高高延迟链路上的吞吐
- **进度**：每个任务的已传字节、速度、剩余时间；队列的总进度
- **暂停与续传**：先写临时文件（本地和远端都叫 `<名字>.<任务标识>.zssh-part`，名字里带任务标识，别的任务和用户自己的同名文件不会被当成缓存），完成后原子替换目标（本地 Windows 用 MoveFileExW，失败时旧文件完好；远端有 `posix-rename` 就用它，没有就走"原文件改名让开 → 新文件到位 → 删备用文件"三步，任何一步失败服务器上都至少有一份完整内容；**不覆盖**时一律用普通 rename，因为 posix-rename 会直接替换已存在的目标）；同一个最终目标同时只允许一个任务写——本地目标按规范化后的路径（8.3 短路径和长路径算同一个）互斥，远端目标的锁是**进程级共享**的，键是「用户名@主机:端口 + 路径」，传输队列（所有标签 / 侧栏的引擎）、编辑器保存、AI 写文件共用同一把。续传时从已有的长度继续，并校验已传部分的末尾一小段，确认没有错位
- **冲突处理**：目标已存在时询问：覆盖、跳过、重命名、续传（仅限目标较小时），可以勾选"对后续文件都这样处理"
- **失败重试**：网络断开时任务进入"等待重连"，连接恢复后自动继续
- **保留属性**：可选保留修改时间和权限
- **流控**：传输的读写不能阻塞同一连接上的终端（遵守 M1 设计文档 5.2 的硬规则）

## 3. 界面

参照 Netcatty 移植视觉。

### 3.1 SFTP 标签（M3-2）

- **SFTP 标签**：主机页可以"打开 SFTP"，开出一个双栏标签
  - 左边本地，右边远端；每一栏都有面包屑路径、返回上级、刷新、显示隐藏文件、过滤、排序
  - 文件列表虚拟滚动，一个目录几万个文件也不卡
  - 两栏之间拖动 = 传输；从 Windows 资源管理器拖进远端栏 = 上传；右键菜单
- **传输队列**：底部可以展开的面板，显示每个任务的状态、进度、速度，可以暂停、取消、重试
- **对话框**：冲突处理、修改权限、新建、重命名、删除确认

### 3.2 终端旁的 SFTP 面板（2026-10-17 用户决定，取代原来的"终端侧边栏"）

终端标签里**从左到右固定**是：终端｜AI 面板｜SFTP 面板，三块同屏，**顺序不能调换**。
SFTP 面板里**远端在上、本地在下**，中间的分隔线可以拖动。

- AI 面板和 SFTP 面板各自独立开关；只开 SFTP 时它紧挨终端；SFTP 永远在最右边
- 宽度沿用 UI-1 的做法：拖左边缘调宽度、双击恢复默认，各自记住，所有终端标签共用。
  SFTP 默认 420px、最小 320px；上下比例也记住（本机设置，不同步）
- 窗口不够宽：终端至少 360px；放不下先把面板收到各自的最小宽度，还放不下就收起 AI 面板
  并提示，之后不自动展开（SFTP 是用户刚打开的，优先保留）
- 标题栏有"文件"按钮开关面板
- **停靠 / 拆回**：把独立的 SFTP 标签拖到**同一台主机**的终端标签上，就停靠成这个面板；
  面板里"在新标签中打开"拆回独立标签。两种方向都保留两栏当前的目录。别的主机的终端
  标签不接受停靠，并提示原因
- **远端栏跟随终端目录**：默认打开终端当前目录；终端里 `cd` 后跟过去；用户在面板里手动换了
  目录就停止跟随。**取目录不能往用户的终端里敲命令、不留痕迹**
- 面板窄时只显示 名称、大小、修改时间（再窄先藏修改时间）；完整的列在独立标签里看
- 从远端栏拖到终端区域 = 把远端路径插入输入行（不执行）
- 终端分屏时，面板跟着当前焦点 pane 的会话

### 3.3 与资源管理器的交互

- **拖入**：从资源管理器把文件 / 文件夹拖到远端栏 = 上传到当前目录（停靠面板和独立标签都支持）
- **拖出**：WebView 里做"拖出到资源管理器"很难，先调研；做不到就用右键"下载到…"替代，
  原因写进报告

### 3.4 右键菜单、内置编辑器、复制粘贴、属性（M3-5）

**用户 2026-10-18 的决定**（原话要求：右键菜单包含 传输、编辑、复制、粘贴、复制路径、删除、修改权限、新建、属性）：

1. **内置编辑器用 CodeMirror 6，开成新标签页**（和终端标签并列）。
2. **双击远端文本文件用内置编辑器**（2026-10-19 用户决定去掉外部编辑器，不再有“双击用内置 / 外部编辑器”和
   “外部编辑器路径”这两项设置，见 R-8 第 0 节）。
3. **复制 / 粘贴**用于「远端 → 远端」（同一台主机，或两台主机之间经本机中转）和「本地 → 本地」；
   **远端和本地之间不做复制粘贴**（那就是上传 / 下载，属于「传输」，保持现有的上传 / 下载 / 下载到… 和拖拽）；
   **不和 Windows 资源管理器的剪贴板互通**——剪贴板是 Z-SSH 内部的，只存在内存里。

#### 菜单

菜单在 `SftpTabView`，独立 SFTP 标签和右侧停靠面板共用，改一处两边都生效。菜单的内容、禁用规则和禁用原因由一个纯函数
（`state/sftpMenu.ts`）按「哪一栏、点在文件 / 文件夹 / 空白处、选了几项、剪贴板里有什么」算出来，组件只负责画和键盘导航，
这样每种情形都能单元测试。

```
打开 / 用内置编辑器编辑
─────  下载到本地（本地栏是「上传到远端」）/ 下载到…
─────  复制 Ctrl+C / 粘贴 Ctrl+V / 复制路径
─────  重命名 F2 / 删除 Del
─────  新建 ▸ 文件夹 / 文件 ；修改权限（只有远端）
─────  刷新 F5 / 属性 Alt+Enter
```

- 右键点在**空白处**：只有 粘贴（到当前目录）、新建、刷新、属性（当前目录）。
- 禁用并**悬停说明原因**：编辑类只对单个文本文件（文件夹、盘符、超过大小上限的不行）；重命名、修改权限只对单个条目；
  名字不是 UTF-8 的条目照旧不能操作；粘贴在剪贴板为空、或者剪贴板来源和这一栏一边是本地一边是远端时禁用，
  提示「远端和本地之间请用上传 / 下载」。
- 快捷键只在**文件列表有焦点**时生效，不抢终端里的 Ctrl+C。
- 菜单位置按菜单**实际高度**避开屏幕边缘（量出来再摆，不写死像素）；子菜单键盘可达。

#### 内置编辑器

- CodeMirror 6，语言包按需加载（shell、conf/ini、yaml、json、xml/html、nginx、python、javascript、sql、Dockerfile、markdown，
  按扩展名和文件名判断，认不出就纯文本）。主题跟随界面明暗，字体字号跟随终端设置。许可证记录在 `AGENTS.md` 和 `NOTICE`。
- **本质上是「应用自己的编辑器窗口」**：后端走完整的一套编辑流程——`eN/content/<文件名>` 放下载下来的内容、
  `eN/state/meta.json` 放恢复记录、`EditSession` 做冲突检测、临时文件 + 改名、属主处理（R-6c 的规则）、实际上传字节的摘要。
  界面按 Ctrl+S 把文本交给后端立刻保存。所以冲突对话框、属主询问、上传失败提示、断线后重试，都是同一份代码、同一组事件，
  不另写一份。
- **编码与换行**：只接受合法 UTF-8（可以带 BOM）。不是 UTF-8、含 NUL 字节（看起来是二进制）、换行符混用（LF 和 CRLF 都有，或有单独的 CR）、
  超过 `MAX_EDIT_BYTES` 的文件**不硬打开**，提示原因并建议下载后再处理。状态栏显示编码和换行（LF / CRLF），保存时按原样写回
  （BOM 带回去，LF 还是 LF、CRLF 还是 CRLF），没改动的部分逐字节不变。
- **未保存的修改**：标签上显示未保存标记；关标签、关这台主机的连接、退出程序都要问「保存 / 不保存 / 取消」。
  编辑内容每隔几秒存一份**草稿**到 `eN/draft/<文件名>`（和 `content/` 分开放，免得被当成「保存」），恢复记录扫描时把草稿也算作
  「未上传的修改」，下次启动出现在「未上传的修改」里。断线时编辑内容留在界面里，保存报明确的错误，重连后可以再保存。
- 本地文件也能用内置编辑器打开：保存时先写同目录临时文件再原子替换；打开后文件被别的程序改过则先提示，不悄悄覆盖。

#### 复制 / 粘贴

剪贴板记：来源（哪台主机、哪个标签 / 本地）、路径列表。多个标签之间共用一份。**只有复制，没有剪切**：
移动文件用重命名（同一台主机内），跨主机、跨磁盘不做“复制后删源”。

| 来源 → 粘贴到 | 复制 |
| --- | --- |
| 远端 → 同一台主机的远端 | 服务器端复制（下面三选一） |
| 本地 → 本地 | 本地复制，走传输队列 |
| 主机 A 的远端 → 主机 B 的远端 | 经本机中转，数据只在内存里过，**不落本地磁盘** |

同一台主机内复制，按顺序选方式，界面和传输列表里写明这次用的是哪种：

1. 服务器声明了 `copy-data` 扩展（OpenSSH 9.0 以上）→ 用它，数据不经过本机；
2. 否则远端是 POSIX shell → 通过**后台执行通道**（不是用户的终端）执行 `cp -a -- '<源>' '<目标>'`，路径用单引号转义
   （`'` 写成 `'''`）；重名的处理（跳过 / 重命名 / 覆盖）在执行前就定好，不依赖 `cp` 自己的覆盖行为；没有字节进度，
   显示「服务器上复制中」和已用时间，结束后核对目标存在、大小一致。`cp` 失败就报错，**不悄悄改成中转**，让用户选
   「改为经本机中转」或取消；
3. 两者都不行（例如 Windows 服务器）→ 经本机中转。

经本机中转的（同主机降级和跨主机）**走现有传输队列**，在传输引擎里加「远端 → 远端」这种方向（进度、暂停、取消、失败重试、续传
都有）。跨主机时两边各用自己的连接，目标端临时文件和互斥规则按 R-6c 的 R01，服务器身份按 M3-5 0a 统一的算法。本地复制大文件同样走传输队列。

重名一律走现有冲突对话框；粘贴到源所在的目录默认建议「重命名」成 `名字 - 副本`；不能把文件夹粘贴进它自己或它的子目录
（远端按规范化后的路径判断，本地按 `pathnorm`）。

#### 属性

右键「属性」或 Alt+Enter：远端显示名称、完整路径、类型（链接显示目标）、大小、权限（`rwxr-x---` + 八进制，旁边「修改」打开现有的修改权限
对话框）、属主和组（uid/gid，服务器给了名字就一起显示）、修改时间、访问时间；本地显示名称、路径、类型、大小、创建 / 修改时间、
只读 / 隐藏。文件夹大小要点「计算大小」才递归统计（可取消，显示进度和个数）；多选显示个数和总大小；空白处显示当前目录的属性。

## 4. 和 AI 的衔接

SFTP 做完后，AI 的工具里再加上传、下载、读文件、写文件（M2 设计文档 2.2 节），同样经过确认与拦截。

## 5. 已知限制

- **非 UTF-8 的远端文件名**（2026-10-17，M3-2 记）：`russh-sftp` 在解码文件名时走有损
  路径（`String::from_utf8(...).unwrap_or_else(lossy)`），公开 API 只收 `String`，客户端
  拿不到原始字节。用有损解出来的名字去操作等于把服务器上的名字改坏，所以我们选择
  **拒绝操作**而不是猜。界面上这类条目显示成灰色、标注"文件名编码不是 UTF-8，暂不支持
  操作"，右键菜单和拖动都禁用（`DirEntry::name_is_utf8 = false` 已经带出来了）。要真正
  支持，需要在我们这一层自己实现 SSH_FXP 帧读写原始字节（约 400 行），或者推动上游暴露
  原始文件名——两张都不在本里程碑里。
