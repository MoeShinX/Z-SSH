# M2 设计：AI 运维助手

2026-10-15 立项。参考 Netcatty 的 Catty Agent，但后端用 Rust 实现，不依赖 Node.js。

## 1. 目标

在终端标签旁边打开一个 AI 面板，用自然语言让 AI 在当前连接的服务器上排查问题、执行命令。

- 默认智能体是 **opencode**，也可以切换成 **codex** 或 **Claude Code**
- Z-SSH 自己不直接调用大模型 API。模型、登录、API key 都由各智能体自己的配置负责（用户决定）
- AI 对服务器的一切操作都经过 Z-SSH，由 Z-SSH 负责确认和拦截

## 2. 架构

```
┌─────────── Z-SSH 主程序 ───────────┐
│  AI 面板（前端）                     │
│     │ IPC                          │
│  智能体驱动层（Rust）                 │──启动、对话──▶ opencode / codex / claude（外部进程）
│     │                              │                        │
│  工具桥（本机 TCP + 令牌）◀────────────────── zssh-mcp.exe（MCP stdio 服务）
│     │                              │       智能体通过它调用工具
│  确认与拦截 → 连接池 → SSH 服务器      │
└────────────────────────────────────┘
```

### 2.1 智能体驱动层

定义一个统一的驱动接口（trait），每个智能体一个实现。驱动负责：

- 启动外部进程
- 发送用户消息
- 把智能体的流式输出（文字、思考过程、工具调用）转成统一的事件发给前端
- 停止当前回合、结束对话

三个驱动用的都是各自 CLI 的正式协议，不用 Node SDK：

| 智能体 | 协议 | 注入我们的 MCP 服务的方式 |
| --- | --- | --- |
| opencode | `opencode serve` 提供 HTTP 接口，事件走 SSE | 配置里的 `mcp` 段（`type: local`） |
| codex | `codex app-server`：标准输入输出上的 JSON-RPC | 配置里的 `mcp_servers` |
| Claude Code | `claude -p --input-format stream-json --output-format stream-json` | `--mcp-config` 加 `--strict-mcp-config` |

Netcatty 的 `electron/bridges/aiBridge/sdk/*Driver.cjs` 和 `codexAppServer/` 里有每种协议的细节和踩坑记录（比如 Windows 上 opencode 冷启动可能超过 30 秒），实现时要逐个参考。

### 2.2 Z-SSH 的 MCP 工具服务（`zssh-mcp.exe`）

- 单独的小程序，放在主程序旁边，用 Rust 的 MCP SDK（`rmcp`）实现，走 stdio
- 智能体启动它时，我们通过环境变量传入两样东西：本机工具桥的端口，以及一个**每次运行随机生成的令牌**。它连回主程序，所有工具调用都转给主程序执行
- 工具桥只监听 `127.0.0.1`，没有令牌的连接一律拒绝

**两层鉴权**（2026-10-16 设计调整，配合"共用一个 opencode 进程"）：

1. **连接层令牌**：只证明"这个 MCP 连接是 Z-SSH 启动的那个 opencode 进程发起的"，不再按对话区分
2. **对话层能力密钥**：每个对话一个随机 128 位密钥（32 位十六进制），工具调用必须把它带上（`run_command` / `read_terminal` / `list_sessions` 都带 `capability` 参数），工具桥按密钥找到对应对话的会话表和作用范围。密钥通过该对话自己的系统提示（opencode 的 `prompt_async` 的 `system` 字段）交给模型；其它对话在 opencode 里是独立的上下文，拿不到这个密钥

密钥错误或已过期（对话已结束）一律拒绝；连接层令牌错误则整条连接直接断开。

**工具（第一版）：**

- `list_targets`：本次对话的**目标列表**，每项包括目标 ID、主机显示名、用户名、是否当前焦点、是否已连接。**不含地址和凭据**（AI-2c 把 `list_sessions` 改名，2026-10-16 用户决定）
- `run_command(target_id, command, timeout_sec)`：在目标上执行命令。默认在用户的终端里执行（见 2.8），终端忙就自动降级到后台 exec 通道，返回 stdout、stderr、退出码和危险等级（危险等级只用于标记，见 2.3）
  - 后台通道：在该会话**所在的连接上新开一个 exec 通道**执行，输出干净、能拿到退出码，不打乱用户的终端状态
  - 输出有大小上限（比如 64KB），超出部分截断并注明
  - 超时默认 60 秒，最长 600 秒
- `read_terminal(target_id, max_lines)`：读目标终端最近的输出，让 AI 能看到用户刚才看到的报错。后端为每个会话保留一份最近输出的环形缓冲（256KB），去掉 ANSI 控制字符后返回
- SFTP 相关的工具（上传、下载、读写文件）等 M3 做完 SFTP 再加

**作用范围**（2026-10-16 用户决定，AI-2c 取代旧规则）：一个 AI 对话的目标列表 = **当前焦点终端的会话**（自动，排第一，标记为"当前"）+ **用户在输入框里 @ 进来的主机**。焦点切到别的 pane/标签时"当前"跟着变；@ 进来的主机保留到对话结束或被移除。**AI 只能操作目标列表里的服务器**，没被 @ 的主机就算在主机库里也看不到、碰不了。工具桥按对话的能力密钥找到对应对话的目标列表来校验。被 @ 的主机如果还没有打开的会话，AI 第一次对它执行命令时自动为它新开一个终端标签（不抢焦点）并走正常连接流程；连上后本次对话复用该会话。详见 2.8。

### 2.3 确认与拦截

两种模式（用户决定），设置页里设全局默认值，AI 面板上可以随时切换：

- **手动**：每次 `run_command` 都弹确认。卡片里显示主机、命令全文、危险等级，按钮是"执行"和"拒绝"
- **自动**：**全部直接执行，不弹任何确认**，危险命令也一样（2026-10-15 用户决定）
  - 原方案是"只拦截危险命令、转人工确认"。AI-1b 验收时实测发现黑名单补不完：卡上没写过的 51 条危险写法漏了 20 条，变量间接调用这类写法原理上无法静态识别。用户看过数据后决定：自动模式全部放行
  - 危险判断（`ai::safety`）保留，**只用来标记，不拦截**：危险命令在工具卡片上标红，审计日志里记为 dangerous
  - 手动模式不受影响；默认仍然是手动

**危险命令规则**（参考 Netcatty 的 `electron/bridges/ai/commandSafety.cjs`），包括但不限于：

- `rm -rf` 作用于 `/`、`/*`、`~` 或系统目录
- `mkfs`、`dd of=/dev/…`、重定向写入 `/dev/sd*`、`wipefs`、`fdisk` 和 `parted` 的写操作
- `shutdown`、`reboot`、`halt`、`poweroff`、`init 0/6`
- fork 炸弹、`chmod -R 777 /`、`chown -R` 作用于根目录
- `iptables -F`、`ufw disable`、`systemctl stop sshd` 这类可能把自己锁在门外的操作
- `curl … | sh`、`wget … | bash`

规则写成纯函数，配大量单元测试。命令里有管道、`&&`、`;`、子 shell 时，要能识别出其中任意一段是危险的。

### 2.8 作用范围与在终端里执行（AI-2c，2026-10-16 用户决定）

**作用范围**（取代旧规则，见 2.2）：

- 目标列表 = 当前焦点终端的会话（自动，第一项，标记"当前"）+ 用户 `@` 进来的主机
- 输入框里打 `@` 弹主机选择：先列已打开的会话，再列主机库里的主机，可搜索、可键盘选择；选中后在输入框上方显示成标签（主机名 + 状态点），可点 × 移除，"当前"那台不可移除
- AI 只能操作目标列表里的服务器；未 @ 的主机不可见。工具桥按对话的能力密钥找到目标列表校验
- 被 @ 的主机没有打开会话时，AI 第一次对它执行命令会**新开一个终端标签**（不抢焦点）走正常连接流程（指纹、密码弹窗照常），取消就返回"用户取消连接"；连上后本次对话复用该会话

**在终端里执行**（参考 Netcatty `electron/bridges/ai/ptyExec.cjs` 等，按 AGENTS.md 署名）：

同时满足才在用户终端里执行：会话有打开的终端 pane、shell 空闲（不在备用屏幕、输出停在提示符、没有输入到一半的命令）、该 pane 上没有另一条 AI 命令在跑、shell 是可识别的 POSIX shell（bash/zsh/sh/dash/ash）。不满足就自动降级到后台通道（2.2 的 exec），工具卡片注明"终端忙，已在后台执行"及原因。fish、Windows 的 cmd / PowerShell 一律走后台。

- 往终端写入：**前面加一个空格**（bash 的 `HISTCONTROL=ignorespace` / zsh 的 `HIST_IGNORE_SPACE` 下不进历史），命令末尾接一个带随机串的结束标记拿退出码，写法要保证命令本身的引号、管道、多行不被破坏；包装脚本里 `trap ':' INT`（Netcatty 同款），停止时发出的 Ctrl+C 让子进程照常被打断、退出码 130 如实带回，结束标记照常打出（否则 bash 会把整段复合命令连标记一起丢掉，工具只能等到超时报"仍在运行"）
- 从环形缓冲截取"命令回显之后、结束标记之前"的输出，去 ANSI，上限 64KB 交给 AI
- **显示**（AI-2d）：包装脚本的回显、开始标记行、结束标记行都不显示给用户——终端里看到的是"提示符 + 命令原文（合成回显）+ 命令输出 + 新提示符"，和自己敲命令一样。过滤只作用在**发给界面的显示数据**上：环形缓冲、结束标记解析和终端状态拿到的仍是原始数据（被吞掉的字节由后端替界面 ack，流控不受影响）。任何"等不到预期内容"的情况（回显被关掉、shell 行为不同、压着的数据过久）都原样放行，绝不吞用户的输出
- **交互**：命令要输入时（`sudo` 要密码、`apt` 问 Y/n）用户可直接在终端里输入，AI 等结束标记
- **超时**：超时后命令**不中断**，继续在终端里跑；工具返回"超时，命令仍在终端运行，最近的输出是……"；命令真正结束时清掉"正在跑"的记录
- **停止**：AI 面板点停止时，如果这个对话**确实**有一条命令正在某个终端里跑，向该终端发送 Ctrl+C；没有在跑的命令就什么都不发（不能打断用户自己跑的东西）
- 命令运行期间用户敲键盘照常发给 shell，不拦截；pane 角上显示"AI 正在执行"
- 审计增加"执行位置"（终端 / 后台）和降级原因；工具卡片显示执行位置

### 2.4 限制智能体在本机的能力

这三个智能体都自带在**本机**执行命令、改文件的工具。作为 SSH 运维助手，它们不应该动用户的 Windows 电脑：

- opencode：配置里把 `bash`、`edit`、`write` 等本机工具设成 `deny`，只放行我们的 MCP 工具
- codex：沙箱设成只读，审批策略设成不允许执行本机命令
- Claude Code：`--allowedTools` 只放行 `mcp__zssh__*`，或者用 `--disallowedTools` 禁掉 Bash、Edit、Write
- 智能体进程的工作目录固定为 `%APPDATA%\Z-ssh\agent-workspace`，不让它扫描用户的其他文件夹

具体的参数名以各 CLI 当前版本为准，实现时要实测，确认本机工具真的被禁用了。

### 2.5 智能体的发现与安装

- **发现**：在 PATH 和常见安装位置查找 `opencode`、`codex`、`claude`，执行 `--version` 确认可用。设置页可以手动指定路径
- **opencode 一键下载**（用户决定）：没找到 opencode 时，在设置页和 AI 面板里提供"下载 opencode"按钮
  - 从 opencode 的 GitHub Releases 下载 Windows x64 版本，解压到 `%APPDATA%\Z-ssh\tools\opencode\`
  - 下载走 Z-SSH 的默认代理设置
  - 显示进度，失败可以重试
  - 下载前告诉用户来源地址和大小（2026-10-16 用户决定：**弹窗确认**，用户点了才开始下载）
- codex 和 Claude Code 不提供下载，没装时给出官方的安装说明

**发现规则：自动发现为主**（2026-10-16 用户决定）：

- **默认自动**：每次打开 AI 面板、设置页点"重新检测"时自动查找，找到就用。设置页显示"已自动发现"、路径和版本
- **手动指定只是兜底**：设置页有"自动 / 手动指定"开关，默认自动；只有切到"手动指定"时填写的路径才生效。手动模式下路径无效要报错，**不回退到自动**
- **自动查找顺序**（找到第一个可用的就停，每个候选都用 `--version` 确认）：
  1. Z-SSH 数据目录下的 `tools\<智能体>\`（一键下载装的位置）
  2. PATH（`.exe` / `.cmd` / `.bat` / `.com`；同一目录里同时有裸 shim 和 `.cmd` 时用 `.cmd`）
  3. npm 全局目录（`%APPDATA%\npm` 或 `npm config get prefix`）、pnpm、volta、scoop 的 shims
  4. 官方安装脚本默认位置：opencode `%USERPROFILE%\.opencode\bin`，Claude Code（AI-4）`%USERPROFILE%\.local\bin`
- **拆开 npm 的包装脚本**：找到 `.cmd` 时解析里面 `%~dp0\...` 引用的真实 exe，直接启动 exe；拆不出来再用 `.cmd`（参考 Netcatty `electron/bridges/ai/shellUtils.cjs` 的 `normalizeCliPathForPlatform`）
- **版本检查**：低于 1.19 的 opencode 有 SQLite 外键 bug，设置页和面板提示"版本过低，建议下载新版"并提供下载按钮
- 做成通用发现模块，AI-3/AI-4 只提供各自的候选位置和最低版本

### 2.5b 共用一个 opencode 进程（2026-10-16 用户决定）

- **所有对话共用一个 `opencode serve` 进程**：第一次用 AI 才启动；**所有对话都空闲 10 分钟后自动关闭**，下次使用再启动。原因是每个进程约占 600MB（整树近 900MB），多个标签同时用会吃掉几个 GB
- 对话之间靠 2.2 的**能力密钥**隔离（不是靠进程隔离）
- opencode 进程的配置注入一次，覆盖所有对话：`mcp` 段挂 `zssh`，本机工具按名字全禁，`mcp` / `plugin` 里的用户自带项关掉；但**用户自己的模型配置要保留**（见下）
- 应用退出时照常关闭整个进程树

### 2.5c 保留用户的模型配置（2026-10-16 设计调整）

AI-2 为了隔离用户的 MCP，把 `XDG_CONFIG_HOME` 指向空目录，结果用户 `opencode.jsonc` 里自定义的模型服务商也读不到了，违反"模型用各智能体自己的配置"。改成：

- 读取用户的 opencode 配置（`%USERPROFILE%\.config\opencode\opencode.json` / `.jsonc` 等 opencode 认的位置），**只抽出模型相关的键**：`provider`、`model`、`small_model`、`enabled_providers`、`disabled_providers`，合并进注入的配置
- `mcp`、`plugin`、`agent`、`permission`、`command`、`instructions` 等一律**不带**
- 配置里的 `{env:...}`、`{file:...}` 引用原样保留，由 opencode 自己解析
- 目标：Z-SSH 里列出的模型与直接运行 `opencode models` 一致

### 2.6 界面

参照 Netcatty 的 `components/AIChatSidePanel.tsx` 和 `components/ai/`：

- 终端标签右侧可以展开的面板，有快捷键和标题栏按钮
- **顶部**：智能体选择（opencode / codex / Claude Code，没装的显示为不可用）、模型选择（智能体能列出模型的话）、手动或自动模式开关、新对话按钮
- **消息区**：流式显示 Markdown；工具调用显示成卡片，包括主机、命令、状态、执行位置（终端 / 后台）、可以折叠的输出；需要确认的命令直接在卡片上点"执行"或"拒绝"（确认按钮和工具卡片是同一张，不要出两张卡片，2026-10-16）
- **输入框**：Enter 发送，Shift+Enter 换行；回答过程中可以停止；输入 `@` 弹出主机选择，选中的主机在输入框上方显示成标签（见 2.8）
- 第一次使用时提示一次：命令的输出会发送给智能体所用的模型服务商

## 4. 风险

- **CLI 协议会变**：三个智能体都在快速迭代，协议和参数可能变化。驱动里要记录适配的版本号，启动时检查版本并给出提示
- **本机工具禁用不彻底**：要实测每种智能体是不是真的不能在本机执行命令。这一项关系到安全，不能只看文档
- **opencode 在 Windows 上冷启动慢**：Netcatty 踩过（启动超时给到 60 秒）
- **输出里有敏感信息**：命令的输出会发给模型服务商。界面上要提示，以后可以加"发送前脱敏"
